# Conveni Fit Ver.3

静的Webアプリ。サーバー・AI API・ログイン不要。`index.html` と `data/` を一緒に公開してください。

## 動作確認
```bash
python -m http.server 8000
```
http://localhost:8000 を開きます。`file://` 直開きではJSONの取得に失敗する場合があります。

## 無料公開
GitHubの公開リポジトリにフォルダの中身を置き、Cloudflare PagesのGit連携で `main` ブランチを指定します。ビルドコマンドは不要、出力先はルート（`.`）。無料枠の最新条件は各サービスで確認してください。

## 自動更新の範囲
- `data/products.json` が編集されmainにpushされるとGitHub Actionsが検証し、更新履歴を自動生成します。
- Cloudflare PagesはGitの変更に応じて再デプロイします（連携設定が必要）。
- **公式サイトからの自動取り込みは未実装・無効**です。`check-sources.yml` は定期実行されますが、許可確認と連絡先の設定が終わるまでアクセスしません。
- 公式ページのHTMLが変わっただけでは栄養情報の正確性を検証できません。自動公開は「証拠URL、確認者、確認日、価格、kcal、たんぱく質」を揃えた `verified` データだけに限定します。
- 初期商品8件はすべて `review` です。公式数値を現在確認できていないため、**献立候補は出ません**。これは誤情報を表示しないための意図的な挙動です。

## 商品を承認する
`data/products.json` の対象レコードを編集：
1. 公式の**商品個別ページ**を `source_url` と `source_evidence` に指定
2. 最新の価格・kcal・proteinを商品単位で確認
3. `verified_at` を `YYYY-MM-DD` で入力
4. `reviewed_by` に確認担当者を記入
5. `status` を `verified` に変更
6. `python scripts/validate.py` を実行してからpush

栄養値が不明ならnullのまま `review` にしてください。販売終了は `discontinued` とし、提案から除外します。

## 献立について
確認済みの主食・たんぱく質源・野菜がそろい、1食あたり予算内に収まる場合だけ候補を表示します。これは栄養充足を保証する個別指導ではありません。アレルゲン欄は初期段階で網羅的ではなく、店頭表示の確認が必須です。

## 将来の完全自動化
公式API・データ提供契約・利用許諾済み構造化フィードを確保できれば、入力用アダプターを追加できます。取得値の単位・内容量・変更幅を検査し、条件を満たしたデータだけ自動承認する設計へ拡張してください。
